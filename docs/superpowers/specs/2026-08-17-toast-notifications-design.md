# 消息通知：操作结果 toast 气泡 — 设计

**日期**：2026-08-17
**状态**：已确认（brainstorming 完成，用户批准）
**范围**：WebUI 全局通知组件 + 接口管理操作的结果提示
**关联**：延续 2026-08-16 Liquid Glass 换皮后的视觉体系；与 2026-08-17 接口列表增强（复制/排序/撤销）衔接

---

## 1. 背景与目标

改端口号、保存、删除、复制接口、新增接口等操作目前**成功路径无提示**（只有列表/DOM 静默变化），**失败路径全是浏览器 `alert()` 弹窗**——样式与玻璃主题割裂、阻塞操作流。

目标：

1. 引入统一的**消息气泡（toast）**组件，顶部居中横幅风格
2. 五类接口管理操作（改号 / 保存 / 删除 / 复制 / 新增）成功与失败均有气泡反馈
3. 全站失败的 `alert()` 统一替换为气泡；`confirm()` 确认对话框保留

## 2. 已确认的需求决策

| 决策点 | 结论 |
|---|---|
| 气泡位置与风格 | 顶部居中横幅，滑入 + 自动淡出，玻璃主题（用户确认） |
| 失败提示替换范围 | 全部 `alert()` 统一替换（含 WS 服务操作失败、前置校验提示）；confirm 保留 |
| 保存的既有就地反馈 | `lastSaved` 闪烁 + 校验状态保持不变，仅叠加气泡 |
| 组件形态 | 新增 `public/toast.js` ESM 模块，零依赖；挂载容器由 JS 动态创建，不改 `index.html` |
| 接入方式 | `views/*.js` 与 `app.js` 直接 `import { showToast } from './toast.js'`（同 `router.js` 依赖模式） |
| 持久化 | 无（纯 UI 状态，不落 localStorage） |

## 3. toast 组件

### 3.1 API

`public/toast.js` 导出：

```js
/**
 * @param {'success'|'error'|'info'} type
 * @param {string} message
 */
showToast({ type, message })
```

- 首次调用创建挂载容器：`position: fixed` 顶部居中，flex 列堆叠
- 队列渲染：新气泡从堆叠区底部滑入；每条**自动 2.5s 后淡出**（失败 3.5s）
- 悬停气泡暂停计时；气泡自带关闭按钮，点击立即关闭
- 相同消息连续触发时复用/重置计时（防刷屏）——简易实现：top 消息若与新增消息同文案同类型，重置其计时

### 3.2 视觉（styles.css 新增 `.toast*`）

- 容器：`fixed; top: 14px; left: 50%; transform: translateX(-50%)`，`z-index` 高于 modal 层（弹窗内操作失败也能看到），不拦截点击区之外的指针事件（`pointer-events: none` 容器 + `auto` 气泡）
- 气泡：玻璃面板（`backdrop-filter: blur` + 半透明 `--panel-bg` 系底色）、细边框、圆角、内阴影；左侧语义色指示点 + 图标字符
  - 成功 `success`：绿 `✓`（`--green`）
  - 失败 `error`：红 `✗`（`--red`）
  - 信息 `info`：蓝 `·`（`--cyan`）
- 动画：入场 `translateY(-12px)` + 不透明度过渡（120ms）；退场不透明度 + `translateY(-8px)`（160ms）
- `prefers-reduced-motion: reduce` 时关闭入场/退场动画（与其他组件一致）

## 4. 接入点与文案

### 4.1 HTTP 接口管理（本次核心）

| 操作 | 位置 | 成功文案 | 失败文案 |
|---|---|---|---|
| 改端口号 | `views/port-detail.js` 改号按钮 | `端口已改为 ${newPort}` | 校验：`端口号必须是 1–65535 的整数` / `端口 xx 已存在`；请求失败：`改号失败：…` |
| 保存 | `app.js` 保存按钮 | `已保存` | `保存失败：…` |
| 删除接口 | `app.js` 删除按钮 | `已删除 ${method} ${path}` | `删除失败：…` |
| 复制接口 | `app.js` 复制按钮 | `已复制 ${method} ${path}` | `复制失败：…` |
| 新增接口 | `app.js` 新建流程 | `已创建 ${method} ${path}` | `创建失败：…` |

成功气泡用 `success`，失败用 `error`；校验类提示用 `error`（与请求失败同型，用户可见语义一致）。

> 范围声明：WS 服务详情页（`ws-detail.js`）的保存/删除/新建操作**成功路径不在本次范围**（保持现状静默反馈），只替换其失败 `alert()`；若后续要统一 WS 成功反馈，另行迭代。

### 4.2 顺带统一（用户确认范围）

以下现有 `alert()` 一并替换为 `showToast({type:'error', ...})`：

- `views/port-detail.js`：启用开关切换失败
- `views/port-cards.js`：首页端口启用切换失败
- `app.js`：接口排序失败
- `views/ws-detail.js`：WS 保存/删除操作失败、新建操作失败、切换失败
- `views/ws-services.js`：删除服务失败

`confirm()` 全部保留（确认类对话框语义不变）。

## 5. 错误处理

- `showToast` 纯客户端渲染，无外部依赖；传入未知 `type` 时回退为 `info`
- 操作失败路径中 `catch (e)` 与现有行为一致：消息取 `e?.message || '未知错误'`
- 不吞错、不阻塞原操作流程（toast 在现有 `await`/`catch` 结构内同步调用）

## 6. 测试

无新测试（纯 UI 层，无服务端逻辑变更）。手动验证清单：

1. 改号成功 → 顶部绿条 `端口已改为 5002`；目标端口已占用 → 红条
2. 保存、删除、复制、新增 → 对应绿条；模拟失败（如停止服务后改号）→ 红条
3. 连续操作 → 气泡堆叠不重叠，各自自动消失；悬停暂停
4. modal 打开时操作失败 → 气泡在弹窗之上可见
5. 系统开启「减少动态效果」→ 无动画直接显示/消失
